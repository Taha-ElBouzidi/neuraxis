# How to triage email

A triage is a full sweep, not a skim. Use the person's mail tools (whatever is connected: an MCP server, a mail client, a browser). List the unread messages, up to 50, and read each one for sender, subject, preview, date and thread length. Then search separately for starred unread mail, which is the highest priority whatever else is in the inbox. If no mail tool is connected, say so and stop.

## One category per email, never two

- **Urgent:** words such as urgent, as soon as possible, deadline, action required, end of day, escalation, blocker or critical. Show it at once with full context.
- **Needs reply:** a direct question, a meeting request, an approval needed, an invitation. Show it with a suggested angle for the reply.
- **Waiting on:** an answer to something the person already sent. Mark it as received; nothing to do.
- **For information:** copied in, a status update, an automated notice. One line.
- **Newsletter:** marketing, digests, subscriptions. Count and batch them; do not read each one.
- **Possible spam:** unsolicited, low-value mail. Count it and offer to ignore it; never act on it unasked.

For every urgent and needs-reply item, pull the specific ask, any deadline, and whether there is an attachment.

## Finding the follow-ups hiding in sent mail

List the person's sent mail from the last seven days. For each, check whether a reply arrived in the same thread or from that recipient. Anything with no reply after three days or more is a follow-up candidate ([[reference_how_to_track_follow_ups]]).

## The report

Lead with totals: unread, urgent, needs reply, waiting on, for information, newsletters, spam. Then the urgent and needs-reply items, each with the key excerpt or ask and any deadline. Then the waiting-on items with the key point of each reply, then the follow-up candidates. Each item for information gets a line of about five words. Newsletters get a count and titles, with an offer to summarize.

Then offer next actions instead of taking them: draft replies to the urgent ones ([[reference_how_to_write_an_email]]), draft the follow-ups, summarize a newsletter. Nothing is sent, marked read or archived unless the person chooses it.

## What not to do

- Never invent content; report only what was read. For a very long thread, read it in full or hand it to a helper to summarize, never guess from the preview.
- Keep sensitive content out of the summary beyond what is needed to act on it.
- Past 50 unread, work in batches and say so; never drop the overflow silently.
- If a call fails or a limit stops the sweep, say so and report what did come back.
